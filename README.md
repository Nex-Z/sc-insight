# SC Insight

面向内部监察的数据控制台，React + Vite + Express + PostgreSQL。

## 启动

需要 Node.js 24（使用 `--use-env-proxy` 支持当前机器的网络代理）。

```powershell
npm install
# 首次配置时复制 .env.example 为 .env，并填写数据库连接
npm run db:init
npm run build
npm start
```

打开 http://127.0.0.1:3010 。开发时运行 `npm run dev`，前端位于 http://127.0.0.1:5173 。

当前机器的数据库连接已写入未跟踪的 `.env`，数据库 `sc_insight` 已创建。初始化只创建结构，不安装模拟数据；可重复执行。

## 已实现

- Dashboard、Discover、主播详情、Monitor、Recordings，补充 Alerts 与 Settings 页面。
- 每 60 秒采集公开列表元数据，按平台 ID 去重，写入真实观看人数和状态快照。
- 关键词、地区、观看人数区间、在线/关注/监察名单筛选、排序、分页。
- 收藏、监察名单、个人备注与监控规则持久化。
- 上线、观看人数阈值规则生成站内事件（基于连续采样中的状态变化）。
- 7/30/90 天主播历史查询、24 小时采样总人数曲线、每周采样热图。
- 录像台账空态与存储目录设置：默认 `storage/recordings`，可填写本机或 NAS 绝对路径。更改目录不会移动已有文件。

## 数据含义与接入范围

公开前端接口不是正式服务契约，当前使用 `/api/front/v2/models` 返回的分组列表抽样。界面明确显示“非全站统计”。每次返回的主播集合可能变化，合计人数也会随样本集合变化，不能当作固定人群增长。

历史从首次实际采集开始积累；不会填入模拟曲线。未出现在下一轮列表里的主播保留上次状态，超过 3 分钟标记“待更新”，不会直接判定为离线。元数据适配器只保存用户名、平台 ID、地区、状态和观看人数，不保存直播图像或播放地址。

采集失败会记录错误并保留已有数据。规则仅对已加入监察名单且再次被采样的主播生效，因此这版不是全量、无遗漏的上线/下线监控。外部邮件、Telegram、Webhook 尚未接入。

## 尚待接入

已接入真实 FFmpeg 录制 Worker 和平台无关的 Browser Media Capture，支持排队、停止、归档和播放；浏览器媒体录制不要求绑定主播。已使用公开 HLS 完成端到端录制验证。

这版默认仅绑定 `127.0.0.1`。公网或多用户部署前需要实现身份认证、角色权限及操作审计。

## 检查

```powershell
npm test
npm run build
# 启动服务后运行，需要本机 Chrome
npm run test:e2e
```

浏览器检查覆盖真实数据加载、筛选、详情刷新、备注持久化、规则创建/启停/删除、目录设置、桌面及手机布局。截图输出到 `artifacts/`。检查会创建并删除一条临时规则，并还原所修改的备注。

## NAS / 容器部署

参见 [部署说明](deploy/README.md)。`npm run build:release` 生成独立运行产物，NAS 不需要源码目录。默认访问端口为 `13010`，数据库与录像持久化于部署目录的 `data/`。
